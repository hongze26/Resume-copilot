# 开发者指南

给接手这个项目的人：读完这一页，应该能找到任何一段逻辑在哪、改完怎么验证、新增一个网站或组件库要动哪几个文件。

## 一句话架构

**档案（扩展页面里）+ 页面结构（Content Script 上报）→ 填写计划（纯函数）→ 本人确认 → Content Script 按组件库驱动控件写入并核验。** 保存、提交、投递永远由本人点击。

```
┌──────────── 扩展页面（能读档案） ────────────┐        ┌────────── 网页（Content Script，读不到档案） ──────────┐
│ pages/profile   档案管理、简历识别            │        │ content/index.ts   消息入口、页面变化/滚动/保存点击监听 │
│ pages/panel     侧边栏：扫描→计划→确认→填写    │◀──────▶│ content/site/*     区块与表单在哪（国聘/智联/通用）     │
│   └ core/plan   计划（字段 ↔ 档案路径、置信度）│ 消息   │ content/scan.ts    控件识别：标签、类型、是否为空       │
│   └ adapters/*  站点规则（国聘、智联、通用、定制）│ (core/ │ content/drivers/*  控件驱动：写入、核验、撤销、探测     │
└───────────────────────────────────────────────┘ messages)└────────────────────────────────────────────────────────┘
```

Content Script 只上报**结构**（标签、控件类型、是否为空、选项），从不上报页面上的值；执行时只收到本人确认过的字段和值。

## 三种网站，一条流程

| | 国聘 / 智联（内置适配器） | 定制适配器 | 通用识别 |
|---|---|---|---|
| 区块从哪来 | `site/iguopin.ts`：`.item-section`；`site/zhilian.ts`：`.apply-module` | `site/generic.ts`：文字标题、导航高亮项、打开的弹窗 | 同左 |
| 区块属于哪类信息 | `adapters/<站点>/rules.ts` | 定制定义，未定义时按标题猜 | 按标题猜（`sections.ts`） |
| 字段对应 | 适配器字典（智联按 `label[for]` 的字段名）→ 语义词典 | 定制字段 → 语义词典 | 语义词典 |
| 之后 | 同一套：计划 → 记录绑定 → 确认 → 驱动 → 核验 → 撤销 |

侧边栏里 `isGenericFlow()` 为真时（通用、定制、或国聘适配器认不出本页），扫描后用 `composeRules()` 把页面区块组装成规则，之后与国聘完全相同。**不要再为某类网站另写一套渲染或扫描分支。**

展开表单：经历类区块点区块里的“添加”；单项区块若只显示文字（“姓名：--”），点区块里的“编辑”（通用识别：`generic.ts` 的 `editButtonFor`，经历类记录旁的“编辑”是改已有记录，不自动点；智联：`zhilian.ts` 的 `openForm`）。

区块键：国聘用规则里的键（`education`…）；通用页面用 `t:标题` / `page:标题` / `dlg:标题`，同一页面内稳定。计划 id 是 `区块键:表单序号`，区块键里可能有冒号，拆分用 `splitGroupId()`。

## 常见改动

### 某个网站的字段没认出来
1. 侧边栏“扫描诊断”导出结构报告（不含填写值），看字段的 `label`、`kind`、`section`。
2. 标签叫法没收录 → `semantic.ts` 加同义词；区块名没收录 → `sections.ts` 的 `TITLES`；选项叫法不同 → `dicts.ts`。
3. 加单元测试（`tests/unit/matcher.test.ts`、`sections.test.ts`）。

### 新增一个组件库（例如 iView）
1. `scan.ts` 的 `LIB_ROOTS`：让扫描把它的根元素认成正确的 `ControlKind`（多数库已列出）。
2. 新建 `content/drivers/<库>.ts`，导出 `drive*`、`snapshot*`、`clear*`、`probe*`，在 `drivers/index.ts` 的 `kitOf` 里登记。
3. 在 `tests/fixtures/` 用**真实组件库**搭一个夹具（参考 `el-real/`：`package.json` 开发依赖 + `scripts/build-fixtures.mjs` 构建），写端到端测试。只看文档猜事件是不够的——Element 1.x 和 2.x 打开下拉的方式就不一样。

### 新增一个内置站点适配器
只有通用识别 + 定制适配器满足不了时才做：`adapters/<站点>/rules.ts`（区块、字段字典）、`content/site/<站点>.ts`（实现 `SiteDom`）、在 `adapters/registry.ts` 和 `content/site/index.ts` 登记。认不出区块时侧边栏会自动退回通用识别。

以智联为例（`site/zhilian.ts`），`SiteDom` 里几个可选项的用法：
- `fieldId`：输入框本身没有 id、字段名只写在 `label[for]` 上（Element 的 `prop`）时，由站点给出稳定字段名，规则就能按字段名对应。
- `skip`：扫描时跳过网站叠加的显示用输入框（“至今”显示框、手机号前的区号）。
- `isSaveButton`：网站的保存按钮不叫“保存”（智联新记录的主按钮叫“添 加”）时，告诉“存回档案”询问哪个按钮是保存。注意 `dom.ts` 的 `assertSafeTarget` 同时会拒绝点击表单里的主按钮“添加/新增/确定”。
- 网站自研的弹窗控件（智联的城市、语言证书弹窗）：驱动放 `drivers/sui.ts`，在 `drivers/index.ts` 里先于组件库判断；计划里用 `regions`（地区，可多选）和 `popup-pick`（按名称在分类树里找）值类型。
- 先填会改变后续字段的项（语种 → 证书栏出现、境外院校 → 海外经历自动带出），然后重新扫描；网站已自动带出同样的值时，`exec.ts` 记为完成。

## 安全底线（改代码前先看）

- `content/dom.ts` 的 `assertSafeTarget`：拒绝点击“保存/提交/投递/报名…”与 submit 按钮；执行期间捕获阶段拦截 submit。新驱动只能用 `safeClick`/`safeMouseDown` 点击。
- 页面已有值默认不覆盖；撤销只恢复“当前值仍等于本次写入值”的字段。
- 敏感字段（政治面貌、婚姻、户口、手机…）只接受“标签完全相等”，中置信直接跳过。
- 家庭成员、附件、签名、声明类区块是 `manual`，不填写（家庭表里的“姓名”不能填成申请人姓名）。
- 网络：发布构建不申请 host 权限；`npm run check:network` 检查源码和 CSP。档案只在本人确认后发往本人配置的 API。

## 存储与备份

- 全部用户数据在 `chrome.storage.local`：`profile`（档案）、`customAdapters`（定制适配器）、`settings`（侧边栏设置）。API 密钥只在 `chrome.storage.session`。读写集中在 `pages/shared/storage.ts`。
- `src/manifest.json` 里的 `key` 用来固定扩展标识：没有它时，浏览器按文件夹路径生成标识，换个文件夹加载就成了另一个扩展，存储是空的。**不要改动或删除这个值**，否则所有已安装用户的数据都会“消失”。它是公钥，可以公开；对应的私钥没有保留，也不需要。上架扩展商店时商店会分配自己的标识，届时上传的包里要去掉 `key`。
- 备份文件格式见 `pages/shared/backup.ts`：顶层就是档案本身，另加一个 `x-backup` 键放定制适配器和设置。导入时先拆开，档案部分走迁移和 Schema 校验，定制适配器经 `sanitizeCustomDefs` 过滤后按 id 合并。新增一类用户数据时，记得加进备份。

## 测试

```bash
npm run typecheck      # tsc
npm test               # Vitest 单元测试（core/ 与 adapters/ 的纯逻辑）
npm run test:e2e       # 构建测试版扩展 + 夹具，Playwright 加载扩展跑端到端
npm run package        # 发布构建 + 网络检查 + 打 zip
```

- 夹具在 `tests/fixtures/`：`gp-like`（React + antd，仿国聘）、`zl-real`（真实 Vue 2 + Element UI 2，按智联页面存档与弹窗 HTML 重建，含城市/证书/技能弹窗、“至今”、学校候选）、`el-real`（**真实** Vue 2 + Element UI 1.4.13 / 2.15，仿“我的简历”分页面 + 弹窗）、`el-like`（静态 Element 风格页，含内嵌框架）、`native`（原生表单；`edit-mode.html` 是“只读展示 → 点编辑”的通用页面）。
- 本地看夹具：`npm run serve:fixtures`，打开 `http://127.0.0.1:4173/el1/`。
- 每个端到端测试都断言：保存按钮点击数与 submit 事件数为 0，除本地夹具外没有网络请求。

## 约定

- 注释和界面文字用中文，说明“为什么”；每个文件第一行写这个文件负责什么。
- 纯逻辑放 `core/`、`adapters/`（能在 Node 单测）；碰 DOM 的放 `content/`；碰档案的放 `pages/`。
- 一个文件一类职责；超过 600 行先考虑拆分。
- 改了行为就改测试和文档（`docs/使用手册.md`、`docs/已知限制.md`）。
